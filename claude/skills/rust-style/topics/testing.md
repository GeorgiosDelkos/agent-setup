# Testing (TST)

Read before writing tests, benches, or test-only code. Core rules TST-1 to TST-3 are in
`../SKILL.md`. Tags and IDs as there. For depth: `rfr-testing`; loom models:
`topics/concurrency.md`.

## Layout

- **TST-4** Integration tests are `tests/<area>_<topic>.rs`, or one binary per slow suite
  as `tests/<suite>/main.rs` declaring a `mod` per topic. A test file that needs features
  starts with `#![cfg(feature = "...")]`; a crate whose suite needs a feature set adds
  `tests/_require_full.rs` holding only `#[cfg(not(feature = "full"))]
  compile_error!("run the tests with --features full");`. Document the test tiers next to
  the feature that enables the slow tier. [ref: T J]

## Compile-time guarantees

- **TST-5** Pin auto traits and lifetime contracts by compilation: `fn assert_send<T:
  Send>() {}` style checks (or `static_assertions`) for what must hold, and
  `compile_fail,E0277` doctests on a `#[cfg(doctest)]` holder item for what must not. Every
  `compile_fail` test carries its error code `[check]` and has a compiling twin that
  differs only in the property under test, so it cannot fail for an unrelated reason (two
  of Jon's suites do today). [ref: J T; house: error code and twin]
- **TST-6** In a published library (PAN-2), every `#[track_caller]` misuse panic has a test in `tests/<area>_panic.rs`
  that installs a panic hook, triggers the panic, and asserts `location.file() ==
  file!()`. [ref: T]

## Generating cases

- **TST-7** Parsers, encoders, collections and algorithms get property tests against a
  simple model: random operation sequences applied to the implementation and to a std or
  naive reference, compared after each step (proptest or quickcheck). [ref: J C B]
- **TST-8** Fuzzing for anything that parses untrusted input or has an independent
  oracle: a generator (bytes to test case) kept separate from an oracle (test case to
  verdict), thin `fuzz_target!`s, `cargo fuzz check` in CI, and each oracle also run as a
  time-boxed `#[test]` (`arbtest(..).budget_ms(1_000)`) so `cargo test` covers it. Expose
  fuzzing internals behind a `fuzzing` feature or `cfg(fuzzing)`, never as public API.
  [ref: C T]
- **TST-9** Same tests across several types or modes: a `macro_rules!` battery, or a loop
  over modes (single- and multi-threaded) inside the test. [ref: B J]

## Storage and file formats

- **TST-18** Code that writes a durable format is tested against the file system's failure
  modes, not only against bad bytes:
  - torn writes: truncation at every byte of the last record, and a tail of zeros (ext4 and
    XFS can extend a file with zeros after a crash);
  - the writer's state after a failed or partial write: it refuses further writes, or the
    docs and a test say why appending is still safe;
  - concurrent writers: an exclusive lock or `O_APPEND`, or a doc comment saying a single
    writer is assumed and who guarantees it;
  - durability: what is synced (`sync_data`) before success is reported, and in what order;
  - recovery: every error the tool can hit on its own data names the next step (a repair
    command, a flag, a documented procedure).

## Test strength

- **TST-19** A test suite is judged by the bugs it catches, not by coverage: coverage says a
  line ran, not that a wrong result would fail a test. Before calling a change tested, run
  `cargo mutants --in-diff <diff>` over it (`git diff main.. > /tmp/x.diff`) and kill or
  explain every missed mutant: add the assertion that fails, or say why the mutant is
  equivalent. `templates/ci/mutants.yml` runs the same check on each PR; keep it unless the
  suite takes more than a few minutes. [house: line coverage passes tests that assert
  nothing; mutation testing does not]

## Golden files and fixtures

- **TST-10** Output-heavy code is tested against checked-in expected files, regenerated
  with `<CRATE>_BLESS=1`; the failure message names the variable. A missing expected file
  is created on first run. One `#[test]` per fixture, generated by a macro. [ref: C J]
- **TST-11** Regression tests are named after the issue (`fn issue_90()`) or carry the
  minimized failing input as a comment. [ref: J]

## Determinism

- **TST-12** No timing in assertions. Concurrent tests follow CON-20; async tests ASY-16.
  Tests that assume real-time behaviour sit behind a `not(<crate>_no_tuning_tests)` cfg
  that slow CI jobs (sanitizers, emulation) set. [ref: T J]
- **TST-13** Internal state needed by a test is exposed through `#[cfg(test)]` fields or
  methods (a counter, an "is waiting" flag), not inferred from timing. A `pub` helper that
  exists only for tests is `#[doc(hidden)]` with a comment. [ref: J]

## External services

- **TST-14** Mock the transport, not the protocol (a `MockStream` with scripted bytes,
  errors and EOF). Storage code runs each test against an in-memory fake by default and
  against the real service under `#[ignore]`; CI starts the service and runs
  `--include-ignored`. Endpoints come from env vars with local defaults, and a test skips
  when its service variable is unset. Tests sharing external state are serialized
  (`serial_test`). Waiting on a live service uses a configurable timeout, raised in CI.
  [ref: J]
- **TST-15** CLIs are tested end to end by spawning the binary (`std::process::Command`
  with `env!("CARGO_BIN_EXE_<name>")`; `assert_cmd` when the crate already uses it), and their
  argument parsing by `Opt::try_parse_from(args)` compared against the expected library
  options. [ref: J]

## Miri and sanitizers

- **TST-16** Miri skips name their reason on the same line: `#[cfg_attr(miri, ignore)] //
  no fchmod in miri` `[check]`. Slow suites scale counts with `cfg(miri)` (`if cfg!(miri) {
  16 } else { 1000 }`) or gate the whole file `#![cfg(not(miri))]`. Leaks follow UNS-24.
  [ref: T J]

## Benchmarks

- **TST-17** Benchmarks use criterion (`harness = false`, `[lib] bench = false`), live in
  `benches/` or a separate workspace member, and are compiled in CI (`cargo check
  --benches`) so they do not rot. A regression gate compares old and new runs interleaved
  on instruction counts, not wall time. [ref: T J B]
